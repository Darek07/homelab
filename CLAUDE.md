# CLAUDE.md

GitOps repo for a two-node k3s homelab, reconciled by Flux CD from `main` (`ssh://git@github.com/Darek07/homelab`). There is no application code. Everything here is Kubernetes YAML composed with Kustomize. Pushing to `main` deploys, because Flux applies changes within about 1 minute and `prune: true` deletes anything removed from Git.

## Layout and reconciliation

`clusters/dev/` is the Flux entrypoint. It defines these Flux `Kustomization`s:

| Flux Kustomization | Path | Depends on | SOPS decryption |
|---|---|---|---|
| `infrastructure-configs` | `infrastructure/configs/dev` | none | no |
| `infrastructure-controllers` | `infrastructure/controllers/dev` | infrastructure-configs | yes |
| `monitoring-configs` | `monitoring/configs/dev` | none | yes |
| `monitoring-controllers` | `monitoring/controllers/dev` | monitoring-configs | no |
| `apps` | `apps/dev` | none | yes (`force: true`) |

Notes:
- `infrastructure-configs` and `monitoring-controllers` don't decrypt SOPS, so encrypted secrets must not go under their paths. Put them in `*-controllers/dev` or `*-configs/dev` instead, matching the table above.
- `clusters/dev/flux-system/gotk-*.yaml` is generated by `flux bootstrap`. Don't hand-edit it (Renovate bumps it).

Every area uses the same **base / overlay** pattern:
- `<area>/base/<app>/` holds environment-agnostic manifests plus a `kustomization.yaml` that usually sets `namespace:`.
- `<area>/dev/<app>/kustomization.yaml` references `../../base/<app>` and adds env-specific resources, mostly SOPS-encrypted Secrets (`tunnel-token.yaml`, `secrets.yaml`) and sometimes an Ingress.
- `<area>/dev/kustomization.yaml` lists which apps are enabled. To disable an app, comment it out there (e.g. `audiobookshelf` in `apps/dev`, and several VictoriaMetrics variants and `kube-prometheus-stack` in `monitoring/controllers/dev`).

### What lives where
- **apps/**: actualbudget, audiobookshelf (disabled), firefly, homepage, linkding, and `media` (jellyfin, radarr, sonarr, bazarr, sabnzbd, seerr in one shared `media` namespace, with one sub-kustomization per app).
- **infrastructure/controllers/**: `mariadb` (StatefulSet, used by firefly) and `renovate` (CronJob running hourly 08–21 against this repo).
- **infrastructure/configs/**: the `local-path-retain` StorageClass (local-path, `Retain`, stored under `/mnt/<ns>-<pvc>`) and the NetworkPolicy for mariadb, which only admits ingress from the `firefly` namespace on port 3306.
- **monitoring/**: Flux `HelmRelease` + `HelmRepository` pairs. Currently enabled: grafana, kube-state-metrics, prometheus-node-exporter, victoria-metrics-single. Grafana's datasource points to `victoria-metrics-single-server:8428`.

## Validating changes

No CI or tests exist. Before committing, build the overlays you touched:

```sh
kustomize build apps/dev            # likewise infrastructure/{configs,controllers}/dev, monitoring/{configs,controllers}/dev
```

Cluster-side checks: `flux get kustomizations`, `flux reconcile kustomization apps --with-source`, `flux get helmreleases -n monitoring`.

## Secrets (SOPS + age)

- Every Secret in a `dev/` overlay is SOPS-encrypted. Only `data` and `stringData` are encrypted (`encrypted_regex: ^(data|stringData)$`), so metadata stays readable. Flux decrypts with the `sops-age` secret in `flux-system`.
- The rules file is `clusters/dev/.sops.yaml`, which is not at the repo root. sops won't find it automatically when run from the root, so pass it explicitly. Recipient: `age1hxvwy0vc4qr24t8wwmxs66vgz47t2rnepe9wy524v5xnk8r8mswq9gpe5l`.
  ```sh
  sops --config clusters/dev/.sops.yaml -e -i apps/dev/<app>/secrets.yaml
  ```
  The rules file lists this age key under `pgp:`. If sops treats it as a PGP fingerprint, use `--age <recipient>` instead.
- Never commit a plaintext Secret, and never decrypt files in place and leave them in the working tree. `apps/base/homepage/secret.yaml` is a ServiceAccount-token Secret with no data, so it is fine unencrypted.
- Secret names that base manifests expect: `tunnel-token` (key `token`) for cloudflared, plus app-specific ones (`firefly-secrets`, `db-root-credentials`, `linkding`, `homepage-auth-secret`, `mariadb-root`, `renovate-secrets`, `grafana-admin-credentials`).

## Conventions

- **Public exposure**: each publicly exposed app runs its own `cloudflared` Deployment in its namespace (`base/<app>/cloudflared.yaml`, copied from app to app). It reads its token from the `tunnel-token` Secret in the dev overlay. Public routing (hostnames to services) is configured in the Cloudflare dashboard, not in this repo. The public domain is `*.kaermorhenlab.org`.
- **LAN access**: Traefik Ingress (k3s default, `ingressClassName: traefik`) on `<app>.local` hosts.
- **Storage**: PVCs set `storageClassName: local-path-retain` so data survives PVC deletion. A few older apps (linkding, firefly, audiobookshelf) still use the default class.
- **Workloads**: they generally set a pod `securityContext` (non-root UID/GID, `fsGroup`), set `allowPrivilegeEscalation: false`, and use memory request = limit with a small CPU request and no CPU limit. The control-plane node (4 GB laptop) is tainted, so all apps run on a single 32 GB node. Keep resource requests modest.
- **Image tags**: pin exact versions, never `latest` (renovate itself is the only exception). Renovate scans every `*.yaml` (`renovate.json`) and treats `lscr.io` as `ghcr.io`, and linuxserver tags follow `X.Y.Z[.B]-lsN`. Bumps arrive as `chore(deps): ...` PRs.
- **Media stack**: `apps/base/media/README.md` documents the shared `media-data` PVC layout and the manual UI setup each app needs after deploy. Key rules:
  - Apps mount `/data`, or a `subPath` mounted at the same absolute path (e.g. `subPath: usenet` → `/data/usenet`).
  - All apps share GID 2000 via the `media-permissions` ConfigMap (`PGID`/`UMASK`).
  - Each app gets its own UID (jellyfin 2000, radarr 2001, sabnzbd 2002, bazarr 2003, sonarr 2004). Linuxserver images also need a root `busybox` init container that chowns the `/run` emptyDir.
  - New media apps get a sub-folder under `apps/base/media/<app>/` and `apps/dev/media/<app>/`, plus entries in both parent kustomizations.
- **Homepage dashboard**: the service tiles, bookmarks and widgets are static config in `apps/base/homepage/configmap.yaml`. When you add or expose an app, add it there too. If it gets a new public hostname, also update `HOMEPAGE_ALLOWED_HOSTS` in the homepage deployment.
- **Style**: YAML uses 2-space indentation, LF line endings and a final newline (`.editorconfig`).
- **Commits**: Conventional Commits with the app as scope, e.g. `feat(homepage): ...`, `fix(actualbudget): ...`, `chore(renovate): ...`.
